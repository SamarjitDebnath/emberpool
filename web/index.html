● emberpool

A disposable microVM for every piece of code your agent runs.

A Python library that hands out Firecracker microVMs from a warm pool, destroys each one after a single run, and records on the host what the code tried to do over the network.

Pre-alpha · aarch64 Linux · not yet released
View on GitHub Read the docs 
# one fresh VM per run; deny-by-default networking
from emberpool import SandboxPool

async with SandboxPool(size=4, network="allow:pypi.org") as pool:
    result = await pool.run("print(1 + 1)", timeout=10)
    print(result.exit_code, result.stdout)
    for event in result.trace:   # seen by the host, not reported by the guest
        print(event)

Why

A real VM boundary

Each run gets its own Firecracker microVM under KVM with its own kernel, launched through the jailer. Code never shares the host kernel.

Fast from snapshots

One template VM is booted with Python loaded and snapshotted. Sandboxes are restored from it and kept warm.

Evidence, not self-reporting

DNS and connection decisions are made and logged on the host. The sandbox can't hide a lookup or a connection.

How it works

  1. Build once. Boot a template VM, wait for the in-guest agent, snapshot memory and state.
  2. Restore many. Each sandbox gets a fresh jail, a fresh scratch drive and its own network namespace.
  3. Run. Code goes in over vsock; a replacement VM is restored in the background.
  4. Tear down. The VM is destroyed and the host's trace comes back with the result.

Networking is deny by default. Allowlist domain names and emberpool's own resolver answers only those, while nftables on the host admits connections only to the addresses it returned.

What you can trust in a result

FieldRecorded byTrust
traceHost resolver and nftablesComplete; the guest can't alter it
timed_outHostThe host killed the VM
file_changesHost, reading the scratch driveAdvisory; end state only
stdout, exit_codeGuest agentConvenience; code can forge them

Requirements

  • Linux with KVM, aarch64 (the only architecture verified so far)
  • Firecracker v1.18.0 and its jailer, a 6.1 guest kernel with VMGenID
  • Python 3.12+ and uv · runs as root in v0.1
