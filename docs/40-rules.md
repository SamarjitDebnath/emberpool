# Engineering rules

Rules every change must follow. They exist to protect the host from the code running in the sandbox. A change that breaks one is wrong even if its tests pass. If a rule blocks you, stop and raise it; do not work around it.

Related: [scope](00-scope.md) · [decisions](30-decisions.md)

## Trust boundary

1. **The guest is hostile.** Everything that comes from it is untrusted: vsock frames, output, exit codes, scratch-drive contents, timing. Check size and shape before use. Never use guest data to build a path, a command, an nftables rule or a log format.
2. **Enforcement uses host facts only.** Security decisions rely on what the host observes (veth, namespace, process state), never on what the guest reports.
3. **Fail closed.** If any isolation step fails (jailer, namespace, nftables table or set, VMGenID check), the VM does not start, or is killed. Never fall back to a weaker mode.
4. **Always jailed.** Library code runs Firecracker only under the jailer. Unjailed Firecracker is allowed only in tests marked `vm`.
5. **Default deny.** No code path gives a VM network access except through NetPolicy's per-VM allow set.
6. **Never mount a guest-written disk on the host.** A hostile filesystem image is an attack on the host kernel. Read the scratch drive with userspace tools only, with size and entry limits.

## Host commands and privileges

7. **No shell.** Run external commands with `asyncio.create_subprocess_exec` and an argument list. Never `shell=True`, never a command built as a string.
8. **Validated names only.** Every name passed to `ip`, `nft` or the jailer (VM id, namespace, interface, table, set) is generated by emberpool and checked against a strict pattern where it is used. Interface names are at most 15 characters. Domain names in a policy are validated and lowercased when the policy is parsed.
9. **No text interpolation into rulesets.** nftables rules are built only from validated values.
10. **Touch only what emberpool created.** Its own nftables table, its own `ep-` namespaces and interfaces, its own work directories. Never flush the global ruleset, and never delete by wildcard.
11. **Nothing from the host leaks in.** No host environment variables, files or credentials are passed to the guest or placed in a jailer chroot.

## Lifecycle

12. **Every resource has a teardown.** Processes, namespaces, veths, nftables sets, chroots, sockets and scratch drives are released in `finally` or an async context exit. Teardown is idempotent and survives cancellation.
13. **Every wait is bounded.** Each await on the guest or a subprocess has a timeout. Reads have a maximum size, and captured output is capped.
14. **The host kills.** A timeout is enforced by killing the VM process, not by asking the guest.
15. **No reuse.** One VM, one run, then destroy.

## Data

16. **Strict frames.** Length-prefixed, maximum size checked before allocating, strict JSON with expected keys and types. Unknown protocol versions are rejected.
17. **Trace is host-observed only.** It holds DNS and connection events seen by the host. Guest output never goes into it.

## Code

18. **Structure.** Python 3.12, type hints, asyncio. The public API is only what `emberpool/__init__.py` exports. Firecracker-specific code lives only in `_firecracker.py` and `_jailer.py`.
19. **Dependencies.** The guest agent uses the standard library only. Host dependencies are kept minimal, and each new one is justified in its commit message.
20. **Tests.** Fail-closed paths and teardown after errors are tested, not assumed. Tests that need root or KVM are marked `vm`.
21. **Public repo.** No secrets, usernames or local paths in committed files.
22. **Honest numbers.** Timings from a nested-virtualization VM are never reported as benchmarks.
